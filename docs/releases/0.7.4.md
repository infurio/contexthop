# ContextHop 0.7.4

ContextHop now defaults to a coloured selection summary instead of adding a
persistent prefix to every prompt.

- Choose `chop config display summary`, `prompt`, or `off`. Summary shows only
  activated components and their user-defined tags, once at shell startup and
  when the displayed selection changes. Canceled and unchanged selections stay quiet.
- Prompt mode uses one workspace or resource label plus tags. It omits the
  default Kubernetes namespace and avoids repeating the full component breakdown.
- Tag names and colours come from the selection. No hardcoded production marker
  or special tag-name matching is applied.
- `chop status` uses the summary palette while retaining the full observed status.
  `NO_COLOR`, `TERM=dumb`, and redirected status output disable colours.
- Reopening `chop` highlights the last successfully selected visible item in the
  opening tab. Lists remain alphabetical and activation still requires confirmation.

## Upgrade

The old `config prompt-prefix` command and `promptPrefix` YAML field have been
removed. If your configuration contains `promptPrefix`, replace that line with
`display: summary`, `display: prompt`, or `display: off` before using this version.
Omitting `display` selects summary mode. There is no automatic migration.

Open a new terminal or reload your existing shell-integration line after upgrading.
Reapply a selection to populate its saved tag labels in an older session.
